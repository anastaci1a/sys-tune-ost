## First sys-tune-ost release

**sys-tune-ost gives the Nintendo Switch system UI its own soundtrack.** This first release brings together the custom work since [HookedBehemoth/sys-tune v2.1.0-beta.1](https://github.com/HookedBehemoth/sys-tune/releases/tag/v2.1.0-beta.1), from which this project was forked. It builds on the original project's resident audio player, overlay, and MP3/FLAC/WAV support, with a new focus on music that follows the active system screen.

### Independent soundtracks for the system UI

- Separate playlists for **Home Menu, Lock Screen, System Settings, Startup, Loading**, and supported Nintendo applets.
- Home keeps its track, playback position, and queue while you visit other screens, then resumes on return. Other normal applet playlists restart when activated.
- Gameplay is intended to stay silent. The Loading soundtrack covers the initial application launch, not later loading screens or internal game handoffs.
- A random one-shot Startup sound, optional playback after waking, and an optional independent Wake playlist. Disabled Wake options keep their saved settings.

### Playlist management and playback

- Persistent per-screen playlists with ordering, shuffle, repeat Off/One/All, and controls for the currently active soundtrack.
- Adding or reordering songs preserves the playing track when that file remains in the playlist; removing the active song advances playback appropriately.
- A more focused playlist editor with clearer help, improved cursor/row behavior, and batched updates to reduce interruptions.
- Faster transitions through retained Home playback sessions and reduced MP3 startup scanning. Headerless MP3 files can start without a full duration scan, with duration/seek information unavailable for that session.
- Migration support for the earlier single-file applet assignments, while preserving saved settings.

### Volume, fades, and timing

- Independent global and per-soundtrack volume controls, from **0–150%**.
- Separate fades for track boundaries and mid-song state changes, with adjustable durations up to five seconds.
- Optional music attenuation for Nintendo's native **hold-HOME Quick Settings** panel, including its own volume multiplier and configurable hold threshold; opening Tesla/Ultrahand alone is not the intended trigger.
- An Album-video volume multiplier so video playback can reduce the background soundtrack.
- Adjustable Loading Start and End Delays to tune the soundtrack around application-launch timing.

### System-state handling

- Scene-based separation of Home, Lock, and Settings, which share the same underlying system process.
- Coordinated sleep/display/wake handling and queued-audio clearing to reduce music leaking across power transitions.
- Applet-focus and HOME-return handling, plus diagnostics for UI activity, system scenes, power, and Album video.
- The latest qs11 implementation adds Home auto-resume after returning from another screen, lets foreground applets take priority over lingering Settings state, hides inactive Wake-dependent controls, and removes redundant HOME-button activation.

### Installation and compatibility

1. Back up `/config/sys-tune/config.ini` if upgrading.
2. Extract **`sys-tune-ost-2.4.1.zip`** to the SD card root, merging the `atmosphere` and `switch` folders.
3. Fully reboot the console, open the overlay, assign music to the desired playlists, and enable **System UI OST**. It is off by default on a fresh configuration.

Install the **overlay and sysmodule together from the same ZIP**. This source line uses **IPC API 18**. MP3, FLAC, and WAV/WAVE support is inherited from upstream; M4A/AAC is not supported.

### Known limitations

This release contains experimental UI-state detection and still needs broader console validation. Quick Settings attenuation relies on a HOME-hold heuristic rather than an authoritative panel-visibility signal. Loading timing can vary by game, and User Select's soundtrack can overlap a game's own audio.

An intermittent freeze/fatal during an Ultrahand + User Select exit sequence remains unresolved. The latest hardening changes should not be read as confirmation that this crash is fixed. Home resume, Settings/applet transitions, Quick Settings, and sleep/wake behavior also have outstanding regression checks.
